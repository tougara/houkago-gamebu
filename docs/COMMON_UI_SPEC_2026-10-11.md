# 放課後ゲーム部 共通UI設計・安全移行仕様書

- 文書版: Draft 0.2 / 2026-10-11
- 状態: **共通操作補助を全7ゲームに限定導入済み／ゲームの構成変更は未実施**
- 参照基準: GitHub main / `1bc30b96985053e9528ca7d935c923742b133013`（作成前の最新コミット）
- 対象: サイト共通UI + 7ゲーム
- 最重要方針: **既存のゲーム内容・バランス・進行・セーブ・レイアウトを壊さない。変更は逐次承認・最小差分・個別検証を前提とする。**

## 1. 変更禁止・維持する基準

次の内容は明示指示がない限り変更しない。

1. 各ゲームのルール・役職・条件・勝敗・得点計算・確率・時間・ラウンド数・プレイ人数・難易度・落下速度・演出タイミング。
2. 既存のゲーム画面の画像、ロゴ、背景、効果、BGM/SE、ゲーム盤面、カードの意味、色で示すゲーム内情報、主要アクションの位置。
3. プレイヤー名・アイコン・ID、登録名簿、各ゲームの参加設定、スコア・ランキング・実績・途中再開の保存キーとデータ形式。
4. 秘密情報の表示条件、前の手番に戻れない制限、長押し・確認・投票の確定条件、既存の誤操作防止。
5. モバイルでのカード視認性・タップ対象・スクロール動作。全画面の「スクロール禁止」を共通仕様にしない。
6. ゲーム別のデザインテーマ（配色、装飾、キャラクター、背景）を一律デザインで上書きしない。
7. 他ゲームのファイル・CSS・共通状態を、対象ゲームの調整のついでに変更しない。

## 2. 共通UI仕様（現在は提案）

### 2.1 上部ナビ

- 領域の並び: 「もどる」/「ゲーム一覧」/設定アイコン。画面ごとの背景・配色は保持。
- 現在の「← 1個前にもどる」の短縮は**検討案**。実際の安全な戻り先とメッセージを先に検証してから個別適用。
- ナビゲーション内部はゲーム側の `back`/`home` ハンドラーを利用し、外観の部品だけ共有。単純な `history.back()` への一括置換はしない。
- 最優先操作（戻る・ホーム・ゲーム決定）を誤タップしない配置を維持。
- モーダル・長押し・タイマー実行中の後戻りは既存条件を保持。

### 2.2 ボタン体系

| 用途 | 表示の方向性 | 動作ルール |
| --- | --- | --- |
| 次へ進む / 決定 / ゲーム開始 | 主要ボタンを最も強調 | 1つの意思決定につき原則1つ。現行の位置を安易に動かさない |
| 変更 / 設定 / 補助表示 | 控えめな副ボタン | 主操作と明確に区別 |
| やめる / 記録削除 / 破棄 | 警告色と明確な文言 | 必ず現行確認条件を維持 |
| 登録せず戻る / 選び直す | 副ボタン | 未確定変更を保存しない |
| 無効な機能 | 押せない表示＋理由 | 未実装操作をできるように見せない |

- ボタンの最小押下範囲は原則44×44 CSS pxを目標。ゲーム盤面・カード選択は個別に検証。
- 配色のみで状態を判定させない（文字・アイコン・枠も併用）。
- フォーカス、キーボード、タップ、画面回転、長い名前で使えるか確認。

### 2.3 確認ダイアログ

- 共通レイアウトは「何が起きるか」→「続ける/キャンセル」→「確定」。
- ボタン例は「ゲームにもどる」「ゲームをやめる」など意味が明確な言葉を使う。
- 実際の処理・タイマー再開・破棄する情報は各ゲームの現在の実装を保持。
- 画面を統一するためにブラウザ標準の確認を無断で変更・撤廃しない。
- 秘密情報が既に露出した場合の戻り制限は絶対に緩めない。

### 2.4 プレイヤー表示

- **共通の登録名簿**と**このゲームに参加するメンバー**は別の概念。
- 1人ゲーム: モード画面で「現在のプレイヤー［変更］」を表示。変更から全登録名簿、新規登録へ。
- 複数人ゲーム: 現行の参加人数条件を維持。「参加メンバー／人数／変更」を明確に表示。
- 既存の `HoukagoPlayers` API・一意のIDを利用。ゲーム間で選択した参加人数を勝手に揃えない。
- 登録・参加変更が他ゲームの参加状態を変えないか、共通名簿・記録が保持されるか要確認。
- 名前・アイコンの重複制約など現在の登録仕様を勝手に変更しない。

### 2.5 画面見出し・進行情報

- タイトル/補足/進行表示の階層を揃えるが、必要な場合だけ表示する。
- 例: 「2/5人確認済み」「3/10ラウンド」など。秘密内容や回答を漏らす表示は不可。
- タイマーや盤面より見出しを優先して領域を奪わない。
- 情報が増えた分だけ画面を縦に伸ばさず、既存の表示と入れ替え可能か先に検討。

### 2.6 結果画面

- 共通候補: 「同じ設定でもう一度」「設定を変える」「ゲーム一覧へ」。
- 現行の得点・勝敗・ランキング登録タイミングは変更しない。
- 再戦時の秘密配役・お題・ランダム要素の扱いは各ゲームの既存仕様優先。変更は別途承認。

## 3. 画面サイズ・人数別の設計ルール

- **全画面の1画面固定を要求しない。** 情報量に応じてスクロールを許可する。
- スマホ縦持ちを基本。画面高さが不足した場合、重要操作の押しやすさを優先。
- 目安テスト: 幅320/360/390/430px、一般的なPC幅（例: 1280px以上）、短い画面高さ（例: 640/700px）。
- 人数の最小/中間/最大をそれぞれ確認。10人ではカード行数・文字折返し・長い名前に注意。
- 固定ボタンは盤面やスクロール位置と重ならないこと。PCではゲーム内容の最大幅を超えて伸ばさないこと。
- ブラウザUI（アドレスバーなど）で有効表示高さが変わる点を考慮する。
- 高さ不足なら余白・補助説明から縮め、文字・カード・タップ対象を無理に縮めない。
- 特殊画面（秘密情報・長押し、タイマー、パズル・カード配置）は**ゲーム別例外**として扱う。

## 4. 共通化の実装方針

- 最初は**外観トークン・ヘッダー・ダイアログなど狭い範囲の部品**を対象とし、ゲームの進行ロジックへ触れない。
- 共通CSSで全ゲームの既存クラス（例: `.btn`, `.card`, `.screen`）を一括上書きしない。衝突しない名前空間を付ける。
- ゲーム固有のUIはそのまま残し、少量の共通部品を必要な画面だけに適用する。
- 既存 `player-registry.js`, `settings.js`, `resume.js` を一括で書き換えない。
- 既存の保存キー・ゲームID・参加人数設定・記録項目に破壊的変更を加えない。
- 一括変換・全CSS置換・サイト全体のスケール/フォント変更は不可。
- UI移植用の汎用ライブラリが必要なら、まず対象ゲーム限定で検証し、確認後に範囲を広げる。

### 変更1件ごとに必須の確認

1. 着手前に最新版の対象ファイル・最新コミットを再取得する。
2. **変更対象・非対象を明記**。新ルール・新機能は別案件にする。
3. 可能ならテスト用ブランチで小さな差分として実装し、main反映前に確認する。
4. JavaScript構文・画面遷移・押下操作・ゲーム進行・保存/復元を確認する。
5. UI比較: 最小/最大人数、長い名前、アイコン、長い文章、小型スマホ、PC、途中再開。
6. スクリーンショットまたは実機での見た目を確認できない場合は、**公開表示確認済みと言わない**。
7. 失敗した場合は直前の変更だけを戻す。無関係な部分は変更しない。

### 全ゲームの回帰チェック（最低限）

- タイトル→ゲーム設定→開始→途中→結果→再戦/ゲーム一覧
- 「もどる」「ゲーム一覧」での確認と戻り先。確定済み操作を取り消せないこと
- タッチ、長押し、キーボード、タイマー、スクロール、画面の前後切替
- プレイヤー登録・既存名簿・選択ID、ゲームごとの人数設定、プレイ記録・ランキング
- 再読み込み、途中再開、既存保存データ、初回利用と再利用
- 背景・ロゴ・役職カード・音・エフェクト・主要アクションの位置

## 8. 2026-10-11 実装履歴（第1回・既存処理を保持）

利用者から「ゲームの構成・バランスを変えず、可能な共通UI改善を実装」と明示されたため、安全性を確かめられる共通操作補助のみ導入した。

### 実装済み

- `common-ui.js`: 動的に生成される既存ナビに `role`/`aria-label` を補い、「← 1個前にもどる」を「← もどる」へ短縮。ゲームの戻り先・イベント処理は一切変更しない。
- `common-ui.js`: 既存の確認モーダルへ `role="dialog"`/`aria-modal="true"` と見出しとの関連付けを補う（既存指定があれば保持）。
- `common-ui.css`: キーボードでフォーカスした操作要素にだけ明確なアウトラインを追加。ゲーム画面の通常表示と配置は変更しない。
- `games/*/index.html`: 7ゲームに共通補助CSS/JSを読み込むためのタグ各2行だけ追加。
- `games/favorites.js`: お気に入り登録があれば、おすすめ欄のタイトルを「お気に入りのゲーム」に変更。未登録では従来の「おすすめゲーム」。
- `styles.css`: お気に入りの星は34pxのまま、透明なタップ範囲を左右に5pxずつ拡張。

- 全7ゲームで補助CSS/JSの読み込みタグが各1回存在し、JSはゲーム本体の後に読み込む。

## 9. 2026-10-11 スクロール追従する共通ヘッダー

### 実装済み

- 全7ゲームは既存の `.top-nav` を `settings.css` の末尾で `position:sticky; top:0` に変更。高さ・ボタン幅・戻り先・クリック処理・ゲーム進行は変更しない。
- ゲーム一覧は「トップへ」「共通設定」だけを独立した `.games-sticky-nav` へ移し、見出し・おすすめ・ゲームカードは通常どおりスクロールする。
- ゲーム一覧のカテゴリー絞り込みは、固定ナビの下へ移動する `top` オフセットを追加。一般幅66px、520px以下60px。
- トップページは元々1画面でスクロールしないので変更しない。1画面固定のゲームプレイ画面も既存レイアウトを優先する。
- 共通ヘッダーは位置を維持する `sticky` を使用し、`position:fixed` で本文へ重なる方式は採用しない。

### 検証・注意点

- 変更コミットの差分を確認し、触ったファイルは `settings.css` / `styles.css` / `games/index.html` の3つだけ。
- Chromiumによる再現用HTMLテストで、幅360/390/1280pxのスクロール追従とカテゴリー絞り込みとの非重複を確認。
- 実際の公開サイト・実機での動作、各ゲーム全画面（秘密情報、モーダル、役職確認、プレイ中）は未確認。
- 既存のゲーム `game.js` と `game.css`、共有プレイヤー・セーブ・進行処理には変更を加えていない。
- 特定の画面でヘッダーがゲーム領域を覆う場合は、その画面だけの例外で調整し、一律に高さを増やさない。
